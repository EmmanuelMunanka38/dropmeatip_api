================================================================================
  DROP ME A TIP - API TESTING GUIDE (POSTMAN)
================================================================================

Purpose
-------
Step-by-step reference for manually testing every REST endpoint of this
project in Postman. Covers base URL, auth, request payloads, query/URL params,
expected success responses, error cases and their status codes.

================================================================================
1. BEFORE YOU START
================================================================================

Base URL
--------
    http://localhost:3000

All API routes are prefixed with `/api/v1`. Full examples below.

Start the server (development):
    npm run dev

Database must be migrated first:
    npx prisma migrate deploy && npx prisma generate

Environment variables (see `.env` / `.env.example`) that affect testing:
    WEBHOOK_SECRET        -> value required for the payments webhook header
                             (default: dev-webhook-secret)
    PLATFORM_FEE_PERCENT  -> fee % deducted from every donation (default 5)
    RESEND_API_KEY        -> if EMPTY, emails are skipped (logged to console).
                             Testing does NOT require a real key.
    OTP_SECRET / OTP_LENGTH / OTP_EXPIRES_MINUTES / OTP_MAX_ATTEMPTS
                          -> OTP behaviour

IMPORTANT - How to get the OTP code
-----------------------------------
Authentication is passwordless. In development mode the OTP is printed to the
server console (stdout) for every send/register/login request:

    [dev] OTP for user@example.com: 123456

Read that line from your terminal to complete the /auth/verify-otp step.
(If RESEND_API_KEY is set, the code is also emailed via Resend.)

2. GLOBAL CONVENTIONS
================================================================================

Response envelope (success)
---------------------------
    {
      "success": true,
      "message": "optional human-readable message",
      "data": { ... }
    }

Response envelope (error)
-------------------------
    {
      "success": false,
      "message": "reason",
      "errors": [ { "field": "...", "message": "..." } ],   // only on validation
      "stack": "..."                                         // only in dev, 500s
    }

Common status codes
-------------------
    200  OK
    201  Created (register, tier create, payment initiate)
    400  Validation / bad request
    401  Missing or invalid/expired access token
    403  Invalid webhook secret
    404  Resource not found / unknown route
    409  Conflict (duplicate email/phone, related records)
    422  Insufficient balance on withdraw
    429  OTP rate limit / too many attempts
    500  Server / database error

Authentication header (protected routes)
----------------------------------------
    Authorization: Bearer <accessToken>

  The access token comes from /auth/verify-otp (or /auth/refresh-token).
  It expires after JWT_ACCESS_EXPIRES_IN (default 15m).

Webhook secret header (payments webhook only)
---------------------------------------------
    x-webhook-secret: dev-webhook-secret

Phone number format
-------------------
Accepted inputs are normalized to Tanzanian mobile format:
    07XXXXXXXX        -> 2557XXXXXXXX
    +2557XXXXXXXX     -> 2557XXXXXXXX
    2557XXXXXXXX      -> unchanged
Must start with 2556 or 2557 and contain 12 digits total.
Examples: 0712345678, +255712345678, 255712345678.

4. AUTHENTICATION  (/api/v1/auth)
================================================================================

4.1  POST  /auth/register
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/auth/register
    Auth:   none
    Body:   raw -> JSON

    {
      "fullName": "Jane Doe",
      "email": "jane@example.com",
      "phone": "0712345678"
    }

    Field rules:
      fullName  2-100 chars (required)
      email     valid email (required)
      phone     valid TZ mobile (required, see section 2)

    Expected 201:
    {
      "success": true,
      "message": "Verification code sent to your email",
      "data": { "userId": "<uuid>" }
    }

    Error cases:
      400  invalid email/phone/name (validation errors array)
      409  "An account with this email already exists" (email already verified)
      409  "An account with this phone number already exists"
      429  "Please wait X seconds before requesting a new code" (cooldown)

    NOTE: If the email exists but is NOT verified, register re-sends the OTP
    and returns that user's id instead of erroring.

4.2  POST  /auth/login
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/auth/login
    Auth:   none
    Body:   raw -> JSON

    {
      "email": "jane@example.com"
    }

    Expected 200:
    {
      "success": true,
      "message": "Verification code sent to your email",
      "data": null
    }

    Error cases:
      400  invalid email
      404  "No account found with this email"

4.3  POST  /auth/verify-otp
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/auth/verify-otp
    Auth:   none
    Body:   raw -> JSON

    {
      "email": "jane@example.com",
      "code": "123456"
    }

    Field rules:
      email  valid email
      code   4-8 digits (the code printed to the server console)

    Expected 200 (data shape):
    {
      "success": true,
      "message": "Email verified",
      "data": {
        "user": {
          "id": "<uuid>",
          "email": "jane@example.com",
          "fullName": "Jane Doe",
          "phone": "255712345678",
          "username": "janedoe",
          "isVerified": true,
          "bio": null,
          "avatarUrl": null,
          "unitName": "Soda",
          "unitPriceTzs": 2000,
          "payoutPhone": null,
          "createdAt": "2026-10-10T..."
        },
        "tokens": {
          "accessToken": "<jwt>",
          "refreshToken": "<jwt>"
        }
      }
    }

    Error cases:
      400  "No verification code found. Please request a new code"
      400  "Verification code has expired. Please request a new code"
      400  "Invalid verification code"
      404  "No account found with this email"
      429  "Too many failed attempts. Please request a new code" (>5 attempts)

    SAVE the accessToken and refreshToken for the next steps.

4.4  POST  /auth/refresh-token
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/auth/refresh-token
    Auth:   none
    Body:   raw -> JSON

    {
      "refreshToken": "<refreshToken from verify-otp>"
    }

    Expected 200:
    {
      "success": true,
      "message": "Token refreshed",
      "data": {
        "accessToken": "<new jwt>",
        "refreshToken": "<new jwt>"
      }
    }

    Error cases:
      400  "Refresh token is required" (empty body)
      401  "Invalid or expired refresh token"
      401  "Invalid token type"
      401  "User account no longer exists"

4.5  POST  /auth/logout
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/auth/logout
    Auth:   Bearer <accessToken>
    Body:   none

    Expected 200:
    {
      "success": true,
      "message": "Logged out successfully",
      "data": null
    }

    NOTE: Logout is stateless (tokens are client-side). It always returns 200.

    Error case:
      401  missing/expired token

4.6  GET  /auth/me
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/auth/me
    Auth:   Bearer <accessToken>
    Body:   none

    Expected 200 (same user object as verify-otp "user"):
    {
      "success": true,
      "message": "Profile retrieved",
      "data": { ...user object... }
    }

    Error cases:
      401  missing/expired token
      404  "User not found"

6. PAYMENTS  (/api/v1/payments)
================================================================================

6.1  POST  /payments/initiate   (donation)
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/payments/initiate
    Auth:   none
    Body:   raw -> JSON

    {
      "type": "DONATION",
      "creatorUsername": "janedoe",
      "amountTzs": 2000,
      "phone": "0712345678",
      "supporterName": "John Fan",
      "message": "Love your work!"
    }

    Field rules:
      type            "DONATION" (literal)
      creatorUsername non-empty (lowercased server-side)
      amountTzs       positive whole number
      phone           valid TZ mobile
      supporterName   1-100 chars
      message         max 500 chars (optional)

    Expected 201:
    {
      "success": true,
      "message": "Payment initiated, awaiting confirmation",
      "data": {
        "transaction": {
          "id": "<uuid>",
          "reference": "TXN-<ts>-<hex>",
          "type": "DONATION",
          "amountTzs": 2000,
          "feeTzs": 100,
          "netAmountTzs": 1900,
          "phone": "255712345678",
          "message": "Love your work!",
          "supporterName": "John Fan",
          "status": "PENDING",
          "creatorId": "<uuid>",
          "tierId": null,
          "createdAt": "...",
          "updatedAt": "..."
        },
        "push": {
          "provider": "mock",
          "reference": "TXN-<ts>-<hex>",
          "status": "PENDING",
          "message": "USSD push sent to 255712345678. Enter your PIN to complete TZS 2,000."
        }
      }
    }

    Error cases:
      400  validation (bad phone/amount, missing fields)
      404  "Creator not found"

    SAVE the transaction "reference" and "id" for the webhook and status tests.

6.2  POST  /payments/initiate   (membership)
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/payments/initiate
    Auth:   none
    Body:   raw -> JSON

    {
      "type": "MEMBERSHIP",
      "tierId": "<tier uuid>",
      "phone": "0712345678",
      "supporterName": "John Fan",
      "message": "Happy to join!"
    }

    Field rules:
      type           "MEMBERSHIP" (literal)
      tierId         valid UUID
      phone          valid TZ mobile
      supporterName  1-100 chars
      message        max 500 chars (optional)

    Expected 201: same shape as donation, but:
      transaction.type   = "MEMBERSHIP"
      transaction.amountTzs = the tier's priceTzs (ignores any amount you send)
      transaction.tierId = <tierId>

    Error cases:
      400  validation
      404  "Membership tier not found or inactive"

6.3  POST  /payments/webhook
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/payments/webhook
    Auth:   none (uses header secret instead)
    Header: x-webhook-secret: dev-webhook-secret
    Body:   raw -> JSON

    Confirm a payment (mark COMPLETED + credit wallet):
    {
      "reference": "TXN-<ts>-<hex>",
      "status": "COMPLETED"
    }

    Fail a payment:
    {
      "reference": "TXN-<ts>-<hex>",
      "status": "FAILED"
    }

    Field rules:
      reference  non-empty (must match an existing transaction reference)
      status     "COMPLETED" | "FAILED"

    Expected 200 (on COMPLETED):
    {
      "success": true,
      "message": "Webhook processed",
      "data": { ...transaction object with "status": "COMPLETED"... }
    }

    Side effects of a COMPLETED webhook:
      - transaction.status = COMPLETED
      - wallet (created if missing) credited with ledger entries:
          CREDIT = amountTzs
          FEE    = feeTzs (only if > 0)
      - if MEMBERSHIP, a UserMembership row is created
      - an email is sent to the creator (skipped if no RESEND_API_KEY)

    Expected 200 (on FAILED): transaction object with "status": "FAILED"
      (no wallet credit)

    Error cases:
      403  "Invalid webhook secret" (missing/wrong header)
      400  validation (bad reference/status)
      404  "Transaction not found"

    NOTE: Sending COMPLETED for an already-completed transaction is idempotent
    (returns the transaction without double-crediting).

6.4  GET  /payments/transaction/:id
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/payments/transaction/<transactionId>

    Error cases:
      400  invalid transaction id

7. WALLET  (/api/v1/wallet)
================================================================================

7.1  GET  /wallet/balance
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/wallet/balance
    Auth:   Bearer <accessToken>
    Body:   none

    Expected 200:
    {
      "success": true,
      "data": { "balance": 1900 }
    }

    NOTE: balance is computed live as
      SUM(CREDIT) - SUM(DEBIT) - SUM(FEE)
    (net of platform fee). It creates an empty wallet if none exists yet.

    Error case:
      401  missing/expired token

7.2  GET  /wallet/ledger
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/wallet/ledger?page=1&limit=20
    Auth:   Bearer <accessToken>
    Body:   none

    Query params (all optional):
      page   positive integer (default 1)
      limit  positive integer, max 100 (default 20)

    Expected 200:
    {
      "success": true,
      "data": {
        "entries": [
          {
            "id": "<uuid>",
            "type": "FEE",
            "amountTzs": 100,
            "description": "Platform fee",
            "reference": "TXN-<ts>-<hex>",
            "createdAt": "..."
          },
          {
            "id": "<uuid>",
            "type": "CREDIT",
            "amountTzs": 2000,
            "description": "Donation from John Fan",
            "reference": "TXN-<ts>-<hex>",
            "createdAt": "..."
          }
        ],
        "total": 2,
        "page": 1,
        "limit": 20
      }
    }

    Error cases:
      400  invalid page/limit
      401  missing/expired token

7.3  POST  /wallet/withdraw
--------------------------------------------------------------------------
    URL:    http://localhost:3000/api/v1/wallet/withdraw
    Auth:   Bearer <accessToken>
    Body:   raw -> JSON

    {
      "amountTzs": 1000,
      "phone": "0712345678"
    }

    Field rules:
      amountTzs  positive whole number
      phone      valid TZ mobile

    Expected 200:
    {
      "success": true,
      "message": "Payout requested successfully",
      "data": {
        "payout": {
          "id": "<uuid>",
          "userId": "<uuid>",
          "amountTzs": 1000,
          "phone": "255712345678",
          "status": "PENDING",
          "reference": "PAY-<ts>-<hex>",
          "createdAt": "...",
          "updatedAt": "..."
        },
        "newBalance": 900
      }
    }

    Side effects:
      - a Payout row (status PENDING) is created
      - a DEBIT ledger entry is written (atomic, SERIALIZABLE isolation)
      - an email is sent to the creator (skipped if no RESEND_API_KEY)

    Error cases:
      400  validation (bad amount/phone)
      401  missing/expired token
      422  "Insufficient balance. Available: TZS X"

8. SUGGESTED END-TO-END TEST FLOW
================================================================================

  1.  GET  /health                     -> 200
  2.  POST /auth/register              -> 201 (get userId)
      (read OTP from server console)
  3.  POST /auth/verify-otp            -> 200 (save accessToken + refreshToken,
                                          note the generated username)
  4.  GET  /auth/me                    -> 200 (with Bearer token)
  5.  POST /auth/refresh-token         -> 200 (new token pair)
  6.  PATCH /creators/profile          -> 200 (set unitName/price/payoutPhone)
  7.  GET  /creators/:username         -> 200 (public profile)
  8.  POST /creators/tiers             -> 201 (save tier id)
  9.  GET  /creators/tiers/my-tiers    -> 200
  10. PATCH /creators/tiers/:id        -> 200
  11. POST /payments/initiate (DONATION)   -> 201 (save reference + id)
  12. GET  /payments/transaction/:id   -> 200 (status PENDING)
  13. POST /payments/webhook (COMPLETED)   -> 200 (status COMPLETED)
  14. GET  /wallet/balance             -> 200 (balance > 0)
  15. GET  /wallet/ledger              -> 200 (CREDIT + FEE entries)
  16. POST /payments/initiate (MEMBERSHIP) -> 201 (use tier id)
  17. POST /payments/webhook (COMPLETED)   -> 200
  18. POST /wallet/withdraw            -> 200 (payout + reduced balance)
  19. DELETE /creators/tiers/:id       -> 200
  20. POST /auth/logout                -> 200
